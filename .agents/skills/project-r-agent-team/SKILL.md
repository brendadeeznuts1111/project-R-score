# Project R Agent Team Access

## Start

1. Run `dx context`, `dx mcp-status`, and `bun run remote:list` before changing
   any machine configuration.
2. Choose the project identity accepted by `scripts/agent-env.sh`:
   `factorywager`, `cloudflare`, `bet-ticker`, `cascade-mover`, `partners`, or
   `kalshi-bot`.
3. Source the loader and prove session readiness without printing vault values.
4. Use the repository-owned MCP, Reasonix, Pages, or SSH command for the task.

```bash
source scripts/agent-env.sh factorywager
bun run proton:session:ready
```

## Authority boundaries

- Vault custody, PAT-to-vault visibility, session recovery, injection, and SSH
  agent behavior are owned by
  [`proton-integration.md`](../../../docs/harness/tenants/proton-integration.md).
  Do not copy item inventories or expiry dates into this skill.
- Workspace MCP configuration is owned by [`.mcp.json`](../../../.mcp.json).
  `.cursor/mcp.json` is only a symlink and `.vscode/mcp.json` is generated by
  `bun run mcp:sync`.
- Remote hosts are owned by `~/.reasonix/config.toml` and inspected with
  `reasonix remote list`. Project R staging uses the configured
  `factorywager-staging` entry; do not copy IP addresses or SSH usernames into
  the skill.
- Pages delivery and verification are owned by
  [`cloudflare-pages.md`](../../../docs/harness/tenants/cloudflare-pages.md).
  Preview protection belongs to the Pages **Enable access policy** setting; the
  Access token and general Pages or DNS tokens remain separate.
- Current tunnel state is owned by
  [`tunnel-inventory.md`](../../../docs/harness/tenants/tunnel-inventory.md).
  Never resurrect a retired hostname from copied guidance.

## Read-only diagnostics

```bash
dx context
dx mcp-status
bun run mcp:sync:check
bun run remote:list
bun run proton:verify
bun run cloudflare:env
```

Use `PROTON_PASS_AGENT_REASON` for an audited `pass-cli` read. Prefer
`pass-cli inject` or `pass-cli run` through repository scripts; never paste a
resolved value into a prompt, command history, or documentation.

## Mutating operations

- Connect through `reasonix remote connect <configured-name>` only when the user
  requested remote access.
- Inject a durable local cache with
  `bun run proton:inject:factorywager:reasonix` only when the consuming MCP or
  Reasonix command requires it.
- Deploy Pages only after explicit authorization, using the scoped workflow in
  the Pages runbook. Vault loading and deployment are separate actions.
