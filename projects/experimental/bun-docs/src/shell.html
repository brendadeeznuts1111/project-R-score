Lifecycle & Configuration Flags
--idle-timeout <sec> (default 60 • 0-255 • 0=off)
Directly maps to Bun.serve({ idleTimeout }). Sets the default idle timeout for all new connections. Combine with the dynamic server.timeout(req, n) method (via --idle-timeout-per-request) when you need different lifetimes for different endpoints (SSE, WS, long-poll).
--unref
Calls server.unref() right after startup. Prevents the server from keeping the Bun process alive. You will see an explicit ⚠️ warning in the terminal. Essential for non-daemon usage patterns and graceful process exit in tests/CI/scripts.
--ws / --websocket
Activates the websocket handler + /ws (full upgrade with custom req.headers reading + server.upgrade({ headers, data }) response headers) and /api/ws-status. Includes interactive header tester in this modal. Demonstrates Bun client new WebSocket(url, { headers }) support.
--idle-timeout-per-request <sec>
Drives the educational /api/sse endpoint that demonstrates calling server.timeout(req, value) to selectively disable or extend the idle timer on one connection (perfect for EventSource, WebSockets, or chunked responses).

WebSocket Pub/Sub + Custom Upgrade Headers Demo

Requires --serve --ws. Demonstrates the full upgrade handshake with headers:

  • Server reads custom headers from req.headers (or ?x-client-id=... query for this browser tester) before upgrade().
  • server.upgrade(req, { headers: { 'X-...': 'value' }, data }) injects custom response headers into the 101 reply.
  • Bun client: new WebSocket(url, { headers: { 'Authorization': '...' } }) — headers arrive on the server.

Use cases: JWT auth tokens, client IDs, API keys, cookies on upgrade, protocol metadata. Open multiple tabs with different X-Client-Id values to see them in the logs and /api/ws-status.
