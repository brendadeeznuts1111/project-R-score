# Development Standards

Coding conventions for the FactoryWager monorepo. This file owns source-level
choices only. Agent operations live in [`AGENTS.md`](AGENTS.md); task routes in
[`docs/AGENTS.md`](docs/AGENTS.md); install policy in
[`docs/UNIFIED.md`](docs/UNIFIED.md); structure in
[`STRUCTURE.md`](STRUCTURE.md). Load the matching owner instead of copying its
commands here.

Unresolved non-functional requirements route through
[`docs/harness/README.md`](docs/harness/README.md) and `bun run harness:status`.
The concise contributor reference is
[`docs/DEVELOPMENT-STANDARDS.md`](docs/DEVELOPMENT-STANDARDS.md).

## Runtime and terminology

- Runtime and package manager: Bun, pinned by the root package contract.
- Language: TypeScript ES modules.
- Repository shape: `packages/*`, `lib/*`, and selected `projects/active/*`
  workspaces.
- Use **artifact** for something maintained, delivered, or proven.
- Use **repository** or **source tree** for Git content.
- Use **proof** or **evidence** for a verified claim, not “it looks fine.”

The repository teaches its contract through domain types, boundaries, tests, and
ratchets. Do not recreate policy as tribal-memory prose.

## Enforced coding contract

| Concern        | Required                            | Avoid                              |
| -------------- | ----------------------------------- | ---------------------------------- |
| Domain values  | Branded types after parsing         | Bare `string` identifiers          |
| Wire input     | `unknown` parsed once at an edge    | Mid-stack re-decoding              |
| Types          | Interfaces and precise unions       | `any`, `as any`, non-null `!`      |
| Exports        | Named exports                       | New default exports                |
| Async work     | `async`/`await` with handled errors | Empty `catch` blocks               |
| Human output   | `lib/console/` helpers              | Raw deep dumps and `console.table` |
| Machine output | `cliOut({ json })` / `jsonOut`      | Pretty prose mixed into JSON       |
| Secrets        | Environment/config owners           | Hardcoded tokens or credentials    |
| Formatting     | Pinned Prettier and ESLint          | Hand-normalized competing style    |

Prefer optional chaining and explicit defaults. Give exported functions an
explicit return type when inference does not make the public contract obvious.
Result unions are appropriate for expected fallible operations.

## Domain values and brands

Domain IDs, credentials, tokens, account keys, zone IDs, and similar values must
not travel through interior APIs as bare strings. Parse at the boundary, then
pass the brand inward.

| Boundary state                 | Constructor                     |
| ------------------------------ | ------------------------------- |
| Untrusted wire/CLI/env/JSON    | `parseXId` or the owning schema |
| Optional input                 | `tryXId`                        |
| Already trusted internal value | `asXId`                         |

Never forge `'' as AccountId`. An intentionally opaque DTO primary key needs
`// brand-ok` on that declaration. Local formatting text, loop variables, and
third-party wire shapes may remain strings until they cross the domain boundary.

Authority: [`lib/types/branded/README.md`](lib/types/branded/README.md) ·
[`lib/types/branded.ts`](lib/types/branded.ts) ·
[branded-ID skill](.agents/skills/branded-ids/SKILL.md).

```bash
bun tools/brand-catalog.ts SessionId
bun run check:brands:all
```

## Wire boundary

[`docs/WIRE_BOUNDARY.md`](docs/WIRE_BOUNDARY.md) owns boundary paths, naming
allowlists, and suppressions. Interior harness code receives concrete domain
types. ESLint rejects `decodeUnknown*` and `unknown` function parameters outside
approved parse/decode/is owners.

```ts
function parseDocs(raw: unknown): Docs {
  // boundary validation
}

function handleDocs(docs: Docs): void {
  // trusted interior
}
```

One concept has one parser and one owner. Extend that owner rather than adding a
second validation path.

## Bun-native APIs

Use the installed Bun CLI and canonical documentation instead of inferred Node
translations. Before introducing an unfamiliar `Bun.*` API:

```bash
bun tools/bun-doc-refs.ts suggest "Bun.secrets"
bun tools/bun-doc-refs.ts url "Bun.stringWidth"
```

Add the returned `// @see <canonical-url>` near executable use. Release claims
must follow [`docs/BUN_DOCS_OPERATE.md`](docs/BUN_DOCS_OPERATE.md); do not turn
the active runtime version into an API introduction date.

For Markdown HTML, reuse presets from
[`lib/markdown/options.ts`](lib/markdown/options.ts). Do not spread ad-hoc
`Bun.markdown.Options` objects or obsolete `headingIds` / `autolinkHeadings`
fields across callers.

## Console output

Use [`lib/console/`](lib/console/README.md) for structured output: `logDepth`,
`logTable`, and chrome helpers for humans; `cliOut` or `jsonOut` for machine
consumers. `bunfig.toml [console] depth = 6` is the default. Runtime flags
precede the subcommand: `bun --console-depth=N run -`.

The console-format gate blocks new raw `console.table`, `console.dir`, direct
`Bun.inspect.table`, and pretty-JSON console dumps unless a deliberate
`// console-ok` suppression documents the exception.

## Tests and proof

- Use `bun:test`; place root harness tests under `tests/` and product tests with
  their owning workspace.
- Prefer Arrange → Act → Assert and cover boundary failures on public surfaces.
- Match proof to the claim: unit and type checks prove internal properties; user
  and operator claims require evidence at that boundary.
- Promote the artifact that passed validation. A privileged rebuild needs a new
  proof chain.
- Use named scripts from `package.json`; do not copy a second command catalog
  into documentation.

Development uses `bun run test:watch`; staged hooks select affected checks;
merge authority is `bun run bun:ci` as defined in `AGENTS.md`.

## Security and configuration

- Validate external data before branding it.
- Do not use `eval` or the `Function` constructor on untrusted input.
- Read ports, hosts, Cloudflare/R2 settings, and credentials through their
  owners in `config/ports.ts`, `config/r2-env.ts`, and `lib/security/`.
- Keep tokens out of source, documentation examples, prompts, and shell history.
- Domain and deployment specifics route through
  [`docs/AGENTS.md`](docs/AGENTS.md).

## Change discipline

Keep one canonical pattern after a migration. Remove compatibility prose and
wrappers when their callers are gone. Preserve unrelated dirty files, use
disjoint worktree lanes, and deliver verified changes through the repository's
PR workflow.

Do not resurrect deleted root parking areas such as `data/`, `factorywager/`, or
`kimiremote/`. Nested products may own separate repositories only under the
documented `projects/active/` boundary.
