## Terminology: artifact, not codebase

Per [harness durable-systems guidance](https://github.com/lopopolo/harness-engineering/blob/trunk/docs/durable-systems/README.md) ([replace “codebase” with “artifact”](https://x.com/_lopopolo/status/2076878736507736390)):

| Prefer | Avoid | When |
|--------|--------|------|
| **artifact** | codebase | The thing delivered, validated, maintained, or proven (source tree, package, release, report, dataset, doc set) |
| **repository** / **source tree** | codebase | The git tree or files as a location |
| **harness** | “the framework around agents” (vague) | Checks, brands, docs, tools, pre-commit gates that shape agent work |
| **proof** / **evidence** | “it looks fine” | What establishes a claim at the user or ops boundary |

Source is one **replaceable realization** of durable contracts (specs, brands, boundaries, tests). Specs, brands, and ratchets outlive any single implementation pass. See also [Stop Treating Code as the Artifact](https://hyperbo.la/w/code-is-not-the-artifact/).

In docs and agent prose: write “across the artifact”, “migrate the artifact”, “prove the artifact”—not “across the codebase”.

## Domain strings (harness rule) — mandatory for agents

**Domain types replace bare `string`.** Identifiers, credentials, session tokens, account keys, zone IDs, and other domain-valued text must not travel as unbranded `string` inside the harness after the boundary.

**Enforcement:** pre-commit runs `bun tools/branded-id-check.ts --staged --strict` with **no baseline**. New properties **and** mid-line function parameters (`function f(sessionId: string)`) fail the commit. Use brands from [`lib/types/branded.ts`](lib/types/branded.ts) or justify with `// brand-ok`.

This follows harness [domain modeling](https://github.com/lopopolo/harness-engineering/blob/trunk/docs/domain-modeling/README.md): [parse, don’t validate](https://lexi-lambda.github.io/blog/2019/11/05/parse-don-t-validate/); [branded identifiers](https://x.com/_lopopolo/status/2076191023500611843); [boundary-only decoding](https://x.com/_lopopolo/status/2076200856681357613). Local pattern: [hyperbo.la build](https://github.com/lopopolo/harness-engineering/blob/trunk/docs/domain-modeling/hyperbola.md) (`HyperUrl` instead of raw URL strings between packages).

| Layer | Rule |
|-------|------|
| **Wire / CLI / env / JSON** | Accept `unknown` or `string`; **parse once** with `parseXId` / schema |
| **Optional config** | `tryXId` — never forge empty brands |
| **Known-good internal** | `asXId` when the value is already trusted |
| **Internal APIs** | Parameter types are brands (`SessionId`, `AccountId`, …), not `string` |
| **Display / logs** | May stringify at the edge; do not re-parse mid-stack |

```bash
bun tools/brand-catalog.ts          # discover domain|BrandName
bun run check:brands                # unbranded ID surface (manifest-driven)
bun run check:brands:types          # SessionId ≠ UserId (tsc)
bun run check:brands:all
```

Stable import: [`lib/types/branded.ts`](lib/types/branded.ts). Map: [`lib/types/branded/README.md`](lib/types/branded/README.md). Skill: [`.agents/skills/branded-ids/`](.agents/skills/branded-ids/).

**Bare `string` is fine for:** local loop variables, pure text formatting, non-domain literals, and third-party API shapes **until** they enter our domain—then parse at that boundary.

**Do not:**

- Use `string` for domain IDs in public/harness function signatures
- Write `'' as AccountId` or other empty forges
- Re-validate the same domain invariant in every caller (own it once at parse)

## Enforced conventions

ESLint + pre-commit harness enforce these. Remediation CLIs live under `scripts/fix-*.ts`.

| Rule | Do | Don’t |
|------|----|--------|
| Logging | `console.info` / `warn` / `error` | `console.log` |
| Types | `unknown` + guards, real interfaces, **brands for domain strings** | `any`, `as any`, bare `string` for domain IDs |
| Exports | Named exports | `export default` |
| Nullability | Optional chaining / defaults | Non-null assertions (`!`) |
| Errors | Handle or rethrow | Empty `catch` blocks |
| Secrets | Env via `config/ports.ts`, `config/r2-env.ts` | Hardcoded tokens/keys |

```bash
bun run fix:console-log
bun run fix:scan-any-types
bun run fix:scan-default-exports
bun run fix:scan-non-null-assertions
```

### TypeScript habits

- Prefer interfaces for object shapes; **branded IDs** for domain identifiers.
- Explicit return types on public / exported functions when the type is non-obvious.
- Prefer `async`/`await` over long `.then()` chains.
- Result-style unions (`{ ok: true; value } | { ok: false; error }`) are fine for fallible ops.
- **One concept, one owner** — extend the existing brand/module; do not invent a second parser for the same domain value.

### Wire boundary (decode / `unknown` params)

Harness-engineering (Ryan Lopopolo): **parse once at the edge**, then pass domain types inward.

| Rule | ESLint | Meaning |
|------|--------|---------|
| No `decodeUnknownSync` / `decodeUnknown*` outside boundary | `harness/no-decode-unknown-outside-boundary` (**error**) | Effect/Schema-style decode only in `lib/types/branded/**`, `**/boundary/**`, `**/wire/**`, `**/ingress/**`, or inside a `parse*` / `decode*` / `is*` owner |
| No `unknown` as a function parameter outside boundary | `harness/no-unknown-function-param` (**warn** harness-wide; **error** on `lib/types`, `lib/security`, `lib/core`) | Prefer brands / concrete types; `unknown` only on parse*/decode*/type-guard owners |

Implementation: [`config/eslint/plugin-harness/boundary.ts`](config/eslint/plugin-harness/boundary.ts). Thesis: [lopopolo/harness-engineering](https://github.com/lopopolo/harness-engineering).

```ts
// ❌ mid-stack
function handle(docs: unknown) { … }
decodeUnknownSync(schema)(raw)

// ✅ edge
function parseDocs(raw: unknown): Docs { … }          // name marks boundary
function handle(docs: Docs) { … }                     // trusted inward
```

### Bun APIs

Before using an unfamiliar `Bun.*` API, resolve the canonical doc — do not guess signatures:

```bash
bun tools/bun-doc-refs.ts suggest "Bun.secrets"
bun tools/bun-doc-refs.ts url "Bun.stringWidth"
```

Add `// @see <canonical-url>` near the usage (or `bun tools/bun-doc-refs.ts annotate --write <files>`). Pre-commit blocks staged Bun API use without refs. Details: [`AGENTS.md`](AGENTS.md).

### Console / inspect depth

Use `inspect()` / `logDepth()` from [`lib/console-depth.ts`](lib/console-depth.ts) for structured dumps — not raw deep `console.log(obj)`. Flag/env: `--console-depth=N` / `BUN_CONSOLE_DEPTH` (default `4`). Tests: [`tests/console-depth.test.ts`](tests/console-depth.test.ts).

## Commands that matter

Prefer named root scripts over ad-hoc paths:

```bash
bun run install:all          # workspace install (isolated + global store)
bun run install:verify       # cache / links / no ./~ drift
bun run validate:workspaces  # workspace coverage
bun run packages:list        # inventory (+ triage)
bun run lint                 # eslint on lib/
bun run lint:harness         # harness eslint config
bun run lint:bun-native      # Bun-native gate

bun run dev                  # platform server
bun run dashboard            # live dashboards
bun run deployment:readiness
bun run build:affected
bun run test:affected
```

## Testing & proof

- Runner: **Bun test** (`bun test`, `*.test.ts` / `*.spec.ts`).
- Root harness examples: `tests/` (e.g. `tests/console-depth.test.ts`, `tests/branded-types.test-d.ts`).
- Prefer Arrange → Act → Assert; cover edge cases on public surfaces.
- Project-local tests live next to each app under `projects/active/`.
- **Proof matches the claim** ([harness proof thesis](https://github.com/lopopolo/harness-engineering/blob/trunk/docs/proof/README.md)): unit/type gates prove internal properties; user/ops claims need evidence at that boundary. Prefer promoting the **same artifact** CI validated—do not rebuild under a more privileged job without a new proof chain.

## Security & config

- Ports / hosts: `config/ports.ts` (env-overridable).
- R2 / Cloudflare: `config/r2-env.ts` — required deploy env: `CLOUDFLARE_API_TOKEN`, `R2_ACCOUNT_ID`, `WIKI_DEPLOY_PATH`, `R2_BUCKET_NAME`.
- CORS: `CORS_ALLOWED_ORIGINS` (comma-separated; empty = allow all).
- Bind: `SERVER_HOST` (default `localhost`).
- No `eval` / `Function` constructor on untrusted input; validate wire data before branding (`parse*`).

---

## Delivery

- Conventional commits; pre-commit: repo hygiene, harness lint, branded IDs, Bun doc-refs.
- Parallel agent lanes: claim disjoint paths; don’t stage another session’s dirty files.
- Default: verified work → commit + push to `origin` ([project-R-score](https://github.com/brendadeeznuts1111/project-R-score)). Do not default-push to the `cascade` remote.
- Finish migrations in coherent ratchets when practical—leave one canonical pattern as prompt material, not two eras side by side.
