# AGENTS.md

AI agent entrypoint for the FactoryWager monorepo (`~/Projects`). Keep this file
to invariants that must always be loaded. For unfamiliar work, start with the
repository's executable discovery path:

```bash
bun run ai -- discover "<task>" --path <target>
```

Its output is an index, not authority: inspect the returned source and the
owning command's `--help` before acting. [`docs/AGENTS.md`](docs/AGENTS.md) is a
searchable fallback routing corpus, not a required sequential read.

Project R's portable agent-alignment contract is
`config/project-r-agent-contract.json`. `bun run agents:contract:check`
validates the repository declaration; add `-- --installed` on an operator
machine to compare complete packages under `~/.codex/skills`.

## Authority and repository boundaries

- `origin` is this monorepo, `project-R-score`; `cascade` is the private nested
  `cascade-mover-v3` remote and is never the default push target. Runtime
  identity comes from `lib/github-repository-ref.ts` and remote parts from
  `lib/docs/repo-docs.ts`, not a hand-built `REPO_URL`.
- Project policy stays in this repository. Global agent defaults may point here
  but must not copy repository policy or replace repository-owned checks.
- `.mcp.json` is the workspace MCP source of truth. `.cursor/mcp.json` links to
  it; `.vscode/mcp.json` is generated by `bun run mcp:sync`.
- Proton Pass owns credentials. Never paste tokens into prompts or shell
  history. Cloudflare, remote-host, tunnel, and vault procedures are routed by
  [`docs/AGENTS.md`](docs/AGENTS.md).
- Soft Balance, rails, MessageLog, phones, and package Telegram belong to
  `toc-ops-repo` (`ct`), not this repository. This repository only bakes its TOC
  board at `/portal/toc/`.

## Communication precision

Do not append an unrequested caveat, counterargument, or moralizing endcap to a
sharp claim merely to demonstrate balance. Put a boundary condition in the
mechanism when it changes the truth; otherwise cut it.

Prefer **artifact** for what is maintained, delivered, or proven and
**repository** or **source tree** for Git content. Domain-valued strings use
brands after the boundary.

## Operating rules

- **Inspect before editing.** Run `git status` and `bun run lane:status`; keep
  work disjoint from dirty files owned by other sessions. Never sweep unrelated
  changes into a commit.
- **Use worktrees.** The primary checkout tracks `main`; feature work belongs in
  a worktree. Run `bun install` once in a fresh worktree so Husky is wired. Copy
  only required gitignored runtime files from the primary checkout.
- **Keep the index scoped.** When another lane is staging concurrently, commit
  with an explicit pathspec and verify with
  `git diff-tree --no-commit-id --name-only -r HEAD`. Do not reset, restore,
  move, or delete another lane's files.
- **Keep generated artifacts separate.** Commit bakes as their own
  `chore(bake): ...` change or restore only the bake paths owned by your lane.
  Route foreign root directories through `.gitignore`; do not delete them to
  satisfy hygiene checks.
- **Use repository quality tools.** Root quality is pinned Prettier and ESLint.
  Format touched `lib/**/*.ts` with the configured Prettier workflow. Nested
  standalone products may retain their own explicitly pinned toolchain.
- **Use Bun's test lanes.** Development uses `bun run test:watch`; pre-commit
  uses staged gates; push and merge proof use the full suites. Do not replace
  this with `bun-git-hooks` or invent Node-only flags such as `--runInBand`.
- **Deliver through a PR when requested.** When the user requests delivery,
  close a verified batch with a conventional commit and push. `main` is
  squash-only and branch-protected. Start PR bodies from
  [`.github/pull_request_template.md`](.github/pull_request_template.md), keep
  every required heading, and run `bun run bun:ci` before merge. Hosted GitHub
  Actions are not merge authority.
- **Synchronize safely after squash.** `git sync-main` moves `HEAD` with a soft
  reset, so merged paths can remain staged. Clear only known, byte-identical
  paths; never use `git reset --hard` or a repository-wide restore.
- **Record foreign failures.** If a gate fails solely on another active lane,
  record its exact command, output, and owner. Use `SKIP_TEST_CHANGED=1` only
  with that evidence in the commit message.

Detailed task commands and owners live only in
[`docs/AGENTS.md`](docs/AGENTS.md). Shared staged-gate mechanics live in
`.agents/skills/references/agent-tooling.md`; skills should link there instead
of copying the loop.

## Friction feedback

When a repository tool or route causes the same avoidable failure, record the
stable tool and failure code without credentials or raw logs:

```bash
bun run ai -- friction record --tool <entrypoint> --code <stable-code> --path <target>
bun run ai -- friction report
```

Three matching observations are a promotion signal, not an automatic edit. Fix
the owning tool, route, or contract; then record the durable owner and
prevention in `config/ai-friction.json`. Do not add a rule or skill when an
executable default, clearer error, or discoverable command removes the friction.
